# Model coverage

Which Atlas kernels each focus model uses, derived from the real PyTorch model rather than typed by hand. Every op `torch.export` finds, at every shape, is placed on an atlas-kernels kernel, in host C, or in a build-time constant, with a citation to the code that does it. The table is the basis for kernel ablation and optimization, and atlas-mlir `test/test_model_coverage.py` uses the same fixtures to prove that the hand-written device plans (`smol_full_plan.calls()`, `capture_boundaries.validate_inventory`) match the models. This file is generated by `python3 coverage/build_table.py`; do not edit it by hand.

## Files

| File | Role |
| --- | --- |
| `export_ops.py` | Runs `torch.export.export(strict=False)` on one complete inference and writes `fixture/<model>.json` (aggregated op rows with module path, source line, phase, shapes, dtypes, FLOPs, counts, and the ordered projection and attention call indices) and, under the ignored `out/`, the full node list and graph text. |
| `fixture/*.json` | The committed aggregated rows, read by `build_table.py`, its tests, and the atlas-mlir coverage test. |
| `mapping.yaml` | First-match rules that place every fixture row: `atlas:<family>` (a `kernels/<family>/` directory, the family names of the atlas-kernels kernel manifests), `host:<file>`, or `build:<file>`, each with citations. |
| `build_table.py` | Applies the rules and fails on any unmapped row, unused rule, or device-work count that differs from the qualified builds; writes this file and `coverage.json`. `--check-cites ATLAS_MLIR MERLIN ATLAS_KERNELS` also requires every cited file to exist and every family to have a `kernels/<family>/kernel.yaml` manifest of that name. |
| `tests/` | Checks that this file regenerates exactly, that every rule is needed, and that device work matches the builds. |

## How mapping.yaml relates to Merlin's selection.yaml

Merlin's radiance `kernel_library/selection.yaml` is forward-looking: for an op, dtype, and shape it says which library kernel the compiler should select. `mapping.yaml` is a record: for each op the model actually executes it says where that op ran in the qualified Atlas builds (TinyLlama and SmolVLA, default and fast), and the build fails if any op is unaccounted for. The two share the kernel family names, so a future Atlas `selection.yaml` can be checked against this table: every `atlas:<family>` row here is an (op, dtype, shape) instance that selection must route to that family, and every `host:` row is a candidate for a new kernel.

## Regenerate

`build_table.py` needs Python 3 with PyYAML. `export_ops.py` must run in the interpreter, with the model revision and the input, that the Merlin capture used (Merlin `examples/atlas/comparisons/README.md`), so the export sees exactly the captured model. Local paths come from environment variables.

| Model | Interpreter | Model and input |
| --- | --- | --- |
| TinyLlama | Python 3.10.14, torch 2.10.0, Transformers 5.4.0 (`modeling_llama.py` SHA-256 `46d313ec...`, pinned in Merlin `capture_tinyllama_native.py`) | `TinyLlama/TinyLlama-1.1B-Chat-v1.0` at revision `fe8a4ea1ffedaf415f4da2f062534de366a451e6`, BF16, eager attention; the first 128 tokens of Merlin's pinned development corpus (SHA-256 `573e1d24...`, token SHA-256 `24e1d064...`), then two greedy decode steps |
| SmolVLA | Python 3.12.12, torch 2.10.0, Transformers 4.57.1, LeRobot 0.5.1 (the versions `capture_smolvla_policy.py` checks) | `lerobot/smolvla_base` at revision `c83c3163b8ca9b7e67c509fffd9121e66cb96205` with backbone `HuggingFaceTB/SmolVLM2-500M-Video-Instruct` (config SHA-256 `ea6bc123...`); the compiled observation of `lerobot/svla_so100_pickplace` revision `3d6d687a25cdf1565cdf24550814f72d999a861d`, train episode 0, frame 0, noise seed 0 (`observation.npz`, SHA-256 `167d7bbe...`, the `--observation-input` of `capture_smolvla_policy.py`); ten denoising steps |

```sh
PYTHONPATH=$TINY_PACKAGES $TINY_PYTHON coverage/export_ops.py tinyllama --checkpoint $TINY_CHECKPOINT \
  --corpus $TINY_CORPUS --out coverage/out/tinyllama --fixture coverage/fixture/tinyllama.json
$SMOL_PYTHON coverage/export_ops.py smolvla --policy $SMOL_POLICY --backbone $SMOL_BACKBONE \
  --observation $SMOL_OBSERVATION --out coverage/out/smolvla --fixture coverage/fixture/smolvla.json
python3 coverage/build_table.py
```

`--capture-receipt RECEIPT` optionally compares the exported ordered Linear and Conv2d calls with the calls Merlin's forward hooks recorded in a local capture receipt (`capture_tinyllama_full.py` or `capture_smolvla_policy.py` output): module, step, and shapes for TinyLlama; module, shapes, and dtypes for SmolVLA. The committed fixtures record that local-receipt check as PASS: 465 of 465 TinyLlama calls and 1,421 of 1,421 SmolVLA calls.

## Adding a model

Add a loader to `export_ops.py` that builds the model and its exact captured input, export it, add `rules.<model>` and `builds.<model>` to `mapping.yaml` and the model to `MODELS` in `build_table.py`, and rerun until no row is unmapped. Rows that need a kernel the library lacks are that model's kernel work list. Gemma2 (GM) and pi0 have placeholder columns.

## Limits

Placement follows the qualified builds, which place every op identically in default and fast; a build that moves an op needs a rule restricted to its phase or shape. Rules match model source lines and shapes of the pinned library versions, so a new Transformers or LeRobot version needs its rules rechecked. FLOPs count multiply-adds twice and other arithmetic once per element, so they rank work rather than time it. Zero-FLOP rows (views, casts, and index construction) are placed with the code that performs that layout. The export runs on fake tensors, so it checks shapes and structure, not numerics.

## Coverage

A kernel family is marked for a model when at least one exported op of that model runs inside it. `resnet_pool` and `resnet_patch_gather` serve ResNet50, which has no fixture here.
